# T2Editor 릴리즈 관리 절차

## 버전 규칙

### SemVer (Semantic Versioning)
```
MAJOR.MINOR.PATCH

MAJOR: 하위 호환성 없는 변경
MINOR: 하위 호환성 있는 기능 추가
PATCH: 하위 호환성 있는 버그 수정
```

### 예시
- `11.0.0` → `11.1.0`: 새 기능 추가
- `11.1.0` → `11.1.1`: 버그 수정
- `11.1.1` → `12.0.0`: 메이저 업그레이드

## 릴리즈 주기

### 계획
- **Patch**: 필요시 언제든
- **Minor**: 2주마다
- **Major**: 3~6개월마다

### 배포 프로세스
1. 기능 개발 완료
2. 테스트 완료
3. 문서 업데이트
4. 릴리즈 노트 작성
5. 태그 생성
6. 배포

## 릴리즈 노트 형식

```markdown
# T2Editor X.Y.Z

## 배포 설명
간단한 설명

## 업데이트 사항
- 기능 1
- 기능 2

## 패치 사항
- 버그 수정 1
- 버그 수정 2

## 호환성
- PHP: 7.4 ~ 8.4
- 그누보드5: 5.4+
- 라이믹스: 2.1+

## 주의 사항
- 이전 버전과의 호환성
- 변경된 설정

## 다운로드
- [T2Editor X.Y.Z.zip](링크)
```

## 태그 관리

### 태그 형식
```
v{MAJOR}.{MINOR}.{PATCH}

v11.0.0
v11.1.0
v11.1.1
```

### 태그 생성
```bash
git tag -a v11.1.0 -m "T2Editor 11.1.0"
git push origin v11.1.0
```

## 브랜치 전략

### 브랜치 구조
```
main (안정)
├── develop (개발)
│   ├── feature/새기능
│   ├── bugfix/버그수정
│   └── hotfix/긴급수정
└── release/릴리즈준비
```

### 브랜치 보호
- `main`: PR + 리뷰 필요
- `develop`: PR 필요
- `release/*`: 관리자만
